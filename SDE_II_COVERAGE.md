# SDE II — Current scope and evidence

Reviewed 2026-10-12. See [CURRICULUM.md](CURRICULUM.md) for the audited prerequisite map, coverage gaps and review gates. See [the live track](https://manual.christiansoftware.org/en/tracks/amazon-sde-ii/) for the published reading path.

The core focuses on correctness, data structures, algorithms, maintainable implementation, databases, design and independent assessments. The computational foundations now include a bounded binary-float error study with Neumaier compensation and a separate one-pass Welford mean/variance derivation; independent Fraction-based oracles verify their numerical claims on small samples. These tests do not establish measurement accuracy or universally correctly rounded results. Added bilingual Python basics for typed error contracts and context-manager cleanup, and for bounded UTF-8/JSON file validation, duplicate-field rejection and input validation before destructive file opening. Local independent tests check cleanup, invalid cases, file round trips and error-type distinctions; file replacement is not claimed atomic or crash-durable. Fundamental Git and GNU Make chapters now provide separately verified examples of staged snapshots, two-parent merge histories, incremental C rebuilds and phony test targets. Evidence comes from temporary local repositories and compiled C11 projects; it does not establish remote synchronization guarantees or cross-platform binary reproducibility. Multi-file C compilation and process invocation are now covered by separate bilingual chapters: the first compiles and links actual objects and checks missing-symbol failure; the second validates arguments, environment, independent output streams and exit codes through controlled subprocess tests. These exercises verify the local toolchain/process contract, not portability across arbitrary operating systems. The newest bilingual foundations distinguish sequential clocked state and ideal registers from combinational logic, and provide a separately compiled C11 pointer/array example with explicit bounds, storage duration and null-pointer contracts. Tests verify the bounded sample code and model transitions, not physical circuit timing or the absence of all C undefined behavior. The latest foundational increment adds a specification-to-brute-force-to-invariant problem-solving method and procedural module design with pure computational core and explicit I/O boundaries. Both have matched EN/PT articles and independent test oracles. These additions precede the existing algorithm-pattern and OOP chapters. The 2026-10-12 foundations-first correction also publishes control flow/functions, introductory relational SQL and HTTP client-server semantics in matched EN/PT chapters. It moves advanced system-design cases into an optional section instead of positioning reservations, payment reconciliation and failure infrastructure as the central learning objective. The new examples verify finite, local contracts; they do not claim production system validation. The next revision includes paired chapters on entity/value/aggregate modeling with immutable monetary values and explicit domain invariants, Factory Method versus Abstract Factory with format-family compatibility, and a seat-hold system-design case. Executable examples and adversarial regression tests establish only their local specified contracts; actual simultaneous booking, durable idempotency and payment settlement still require database and integration evidence. The 2026-10-12 curricular correction separates optional compiler/VM specialization from the opening Amazon coding path and adds three bilingual, independently testable chapters: architecture dependency boundaries, State/Command contracts and authoritative writes versus asynchronous read models. New in-memory tests check module-import policy, replay rejection and aggregate projection calculations; they do not prove distributed transaction safety, durable deduplication, real multi-process behavior or interviewer readiness. New bilingual prerequisites teach propositional and quantified logic, counterexamples, proof by induction, loop invariants and termination, plus Python's aliasing, mutation, short-circuit evaluation and explicit error contracts. This is an introductory semantics treatment, not a programming-languages or verification course. The core Clean Code/cohesion/coupling chapter is now published as a prerequisite for object design. Builder, Facade and Observer now have tested bilingual examples in addition to Strategy, Adapter and Decorator; remaining specialist patterns and independent evaluation still require further work. Existing broker failover experiments are **electives**, not mandatory SDE II prerequisites. Introductory machine representation and a separately tested five-stage **teaching pipeline** are published; realistic CPU implementation, cache coherence, authenticated cryptographic protocol implementation/PKI, language theory and transport-layer/network security remain **not fully covered**. Successful builds do not establish independent readiness.

A bilingual FCFS/Round Robin chapter now precedes concurrency, with exhaustive finite tick-oracle verification. Real kernel context switching, unbounded fairness, multi-CPU priority scheduling and I/O remain uncovered.

Advanced scheduling now distinguishes MLFQ promotion/aging from transitive lock priority inheritance, with bounded executable tests. It is a model rather than a live Linux scheduler benchmark or real-time guarantee.

A new bilingual introductory allocator model distinguishes external/internal fragmentation and virtual/physical address spaces, with first-fit, best-fit and independent bitmap verification. Production allocator engineering, actual kernel/filesystem I/O testing and real-time/multicore behavior remain beyond the current teaching examples.

File descriptors now have a standalone tested bilingual introduction to shared open descriptions, offsets and an abstract fsync/crash boundary; file layout, hardware failure testing and complete filesystem crash consistency are not certified by these teaching models.

Filesystem foundations now include a bilingual inode/directory/block model and a separate metadata redo-log crash abstraction; independently verified finite sequences do not imply correct Linux/ext4 recovery, real-device durability or a complete filesystem implementation.

A dedicated bilingual IPv4 prefix-routing and positive DNS TTL-cache chapter now precedes the network request overview; its finite reference tests do not certify DNSSEC, resolver correctness, real routing policy or TCP reliability.

TCP fundamentals now include a bilingual independently tested stream-framing decoder and a finite relative-sequence cumulative-ACK example with sender window bounds. No claim of real TCP socket stack, loss recovery, congestion-control implementation, fairness, throughput benchmarks or network packet tracing.

A dedicated PT/EN TCP RTO lesson now derives RFC 6298 smoothing and Karn/backoff using an independent decimal-state reference, alongside a clearly labeled non-RFC-conformant aggregate congestion-window teaching sketch; complete ACK-driven retransmission and congestion-control implementations are not covered.

An independent TLS 1.3 article now illustrates handshake authentication and **RFC 9846** labels with **RFC 5869** SHA-256 HKDF public vectors and separate reference tests. This does not cover actual certificate verification, AEAD, key agreement, secure random generation or production TLS integration.

DNS now has a dedicated bilateral article for RFC 2308 negative-cache keys and SOA TTL, authoritative delegation concepts and CNAME chain bounds, with independent finite tests. No DNSSEC verification, live iterative resolver, glue/bailiwick policy or full DNS wire parser is claimed.

Foundations now include finite set counting, arrangements, collision probabilities, expected distinct categories and Bayes using exact rational examples and independent finite enumeration oracles. Advanced discrete structures, complete statistics and independently assessed exercises remain future work.

Networking now includes bilingual IPv4 fragment offsets, MF/DF and classical PMTU feedback models. Independent finite tests do not establish live IPv4/IPv6 conformance, ICMP trust, live measurement or DPLPMTUD.

Finite binary relations now have an independent bilingual introduction to equivalence classes, partitions, partial orders, DAG reachability and topological constraints. A bounded executable model illustrates closure; it does not certify production schedulers, infinite-set results or independently proctored interview competence. Elementary integer number theory now includes Euclid, Bézout, congruences, modular inversion and repeated squaring, with independent signed-input and modular arithmetic oracles. More advanced number theory, recurrences and computability remain separate gaps.

A bilingual cost-recurrence chapter now derives exact recursion-tree sums, proves closed forms by induction and states the hypotheses of the Master theorem and its non-applicable cases. A separate test oracle evaluates recursive models and boundary contracts. More general recurrences with uneven splits, varied costs, and independent timed exercises remain open.

The third independent practice assessment now combines a contiguous partition dynamic-programming challenge and an idempotent in-memory event projector. Both implementations remain intentionally absent; the public grader checks valid inputs, rejected inputs, idempotent duplicate semantics and caller-owned state. Tests confirm the exercises remain unsolved and catch trivial or mutation-prone submissions. Passing visible fixtures does not certify unseen-case competence or persistent exactly-once semantics.

Assessment IV adds a separate bilingual legacy-code review with independently verified characterization of known pagination, property exposure and input-mutation defects. A new intentionally unsolved function targets a corrected, precisely scoped tenant query, and the public grader checks ordering, counts, validation and mutation boundaries. Its local mock tenant identifier is NOT real authentication, and visible tests do not certify authorization in a deployed service.

A bilingual independent system-design assessment now tests usage metering and invoice reconciliation under delayed event time, conflicting retries, tenant hotspots and bounded recovery. Its numerical models are tested against independent exact-arithmetic oracles, while the architecture rubric is reviewed by people, not CI. This adds practice breadth but does not establish interviewer-grade competence or a production ledger.

Foundations now include finite formal languages, DFAs and epsilon-NFAs with bilingual executable reachable-subset determinization. Independent tests enumerate binary words and compare against a non-determinizing configuration-graph oracle. This supplies language-recognition foundations, not a general lexer, compiler, context-free parser or computability/complexity-theory curriculum.

Context-free grammar foundations now follow automata in both learning tracks. The paired chapters connect PDA stack invariants to recursive parse trees and generalized Earley-style chart recognition with independently tested left recursion and nullable productions. Tests establish bounded behavior, not a production-grade compiler or optimal Earley complexity. Lexer construction, parse forests, type checking, Turing machines and P/NP remain distinct gaps.

A small bilingual compiler exercise now translates bounded arithmetic source through ASCII lexing, a precedence-climbing AST, a postorder stack-bytecode compiler and an exact rational VM. Cross-checked against a restricted independent host AST evaluator plus explicit stack-invariant tests; no source-language `eval`/`exec` is used. It is not a typed language, secure sandbox or production compiler. Symbol tables, static types, semantic analysis, optimization, general control flow and code generation remain planned.

Static typing now follows the bilingual expression compiler through `static-types-lexical-scopes`: strict `Int`, `Rat`, `Bool` checking; lexical `let` binding and shadowing; Boolean conditions and equal-typed branches; typed bytecode and independent AST-based checks. The bytecode generated by this limited compiler is tested; no guarantee covers forged VM programs, runtime division by zero, general typing soundness for full languages, native code or execution isolation. Further function, mutation, closure and type-inference chapters are planned.

The language curriculum now extends static types with first-class typed anonymous functions, higher-order calls, immutable lexical closures and an explicit call-frame VM, published in paired `typed-functions-call-frames-closures` chapters. Its direct AST oracle and seeded examples exercise definition-time capture versus dynamic scoping, escaped closures, wrong arity and return annotations, call frames and step budgets. This does not claim recursive language support, mutable captures, formal bytecode verification, real compiler backend or security isolation.

The compiler series now includes `mutable-cells-recursive-functions` in both languages, extending the previous first-class closure VM with explicitly mutable cells shared across lexical captures, controlled type-checked `set`, and restricted typed `let rec` for function literals with a two-stage initialization invariant. Independent direct AST interpretation and bounded tests verify sharing, escaped state, factorial and frame-limit rejection. Mutual recursion, general heap management, a validated bytecode file format and concurrency semantics remain out of scope.

The compiler curriculum adds `lexical-addresses-bytecode-verification`: compiler-resolved `(depth,index)` variable slots replace runtime name search in an optional backend, and abstract interpretation verifies control-flow joins, operand-stack types, lexical scope discipline and recursive initialization before VM dispatch. Independent comparisons use the original name-based VM, direct AST oracle and malformed bytecode. The in-memory verifier is bounded, restricted to forward-only conditional jumps, and **does not** verify serialized adversarial byte streams, guarantee execution resource safety or implement garbage collection.

Compiler infrastructure continuation: `versioned-bytecode-serialization` introduces bounded deterministic v1 JSON with type/slot/code descriptors, SHA-256 corruption detection and strict decoder + typed bytecode verifier gate. `tracing-garbage-collection-reachability` adds an independent, explicit-root heap graph and mark/sweep simulation for closure lifetimes and cycles. New executable contracts include independent semantic oracles and tampered bytecode with recomputed checksums. These chapters do not claim authenticated distribution, integrated VM GC, native machine backend, source-to-machine performance or sandbox isolation.

The bilingual `integrated-vm-mark-sweep-gc` chapter now connects lexical-slot bytecode execution to an explicit-root tracing heap: all call frames provide stack/scope roots, mutable cells update pointer graph edges, recursive closure cycles are reclaimed when unreachable, and temporary initializer roots protect live references across allocation-triggered collection. Independent VM and direct-AST comparisons include bounded randomized cases, collection-frequency invariance and heap exhaustion. Model object IDs are **not host pointers**: the implementation does not provide Python heap isolation, external managed closure handles, production GC, concurrency safety, or a benchmarked memory manager.
