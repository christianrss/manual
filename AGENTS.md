# Engineering Manual — agent instructions

This is a public, bilingual, referenced technical manual. The repository is the source of truth. Never invent facts, sources, test results, or published status.

## Authority and boundaries
1. Read `ARCHITECTURE.md`, `EDITORIAL.md` and the relevant skill before editing.
2. Canonical page identity is frontmatter `id`; EN/PT counterparts use identical IDs and slugs.
3. Content is general and vendor-neutral. Company-specific interview requirements belong **only** in learning tracks, not general chapters.
4. No filler, no motivational rhetoric, no unsupported assertions, no copied proprietary interview questions, no autogenerated empty/stub chapters.
5. State assumptions, invariants, failure modes and complexity. Distinguish guarantees from estimates.
6. Use primary specifications, peer-reviewed papers, textbooks or authoritative maintainers. Keep inline `[1]` style source citations and machine-readable `sources` in frontmatter. External URLs must be genuine.
7. New topic -> paired `content/en/topics/<slug>.md` and `content/pt/topics/<slug>.md`. Translation must preserve semantics and code behavior, not word order.
8. Add a prerequisite only when it is already published, or explain it inline. Circular dependencies prohibited.
9. Track references IDs from `content/data/curriculum.yml`; do not duplicate articles under tracks.
10. Do not edit generated `dist/` files. Never mark unfinished work as complete.
11. Run `python scripts/validate.py && python scripts/build.py && python -m unittest discover -s tests -v` before proposing publication.
12. Report counts and failed checks precisely. No deployment claims without verifying deployment.

## Consistency requirements
- Articles need: question/definition, prerequisites (or self-contained explanation), model & assumptions, worked example, trade-offs/counterexamples, implementation or design procedure, test/verification, exercises, references.
- `updated` is the date of meaningful review, not a manufactured recency signal.
- Cite every externally sourced factual or quantitative claim within the article and list its sources.
- When content cannot be verified, omit or flag it rather than speculate.

## Rewriting existing chapters
- Retain public semantic ID and canonical slug; avoid breaking indexed URLs or study-track references.
- Revisit correctness and examples, not just append more words. Name hidden assumptions, explain intermediate derivations, and include at least one nontrivial counterexample.
- Follow Edition 2 rules in EDITORIAL.md and run *all* Python code fences, in both EN and PT, through tests/test_all_code_examples.py.
- Never mark material as comprehensively complete merely because chapter count or build checks pass.
