# Editorial gate — Clean Code foundations, 2026-10-10

**Publication scope:** one new complete bilingual chapter, `clean-code-cohesion-coupling`, inserted before OOP/SOLID in both curriculum tracks; prerequisite repairs to the existing LLD article and the previously misordered engineering/system-design reading path.

**Independent evidence:** a dedicated Python unittest module enumerates small inventory snapshots against a separately constructed arithmetic expectation, checks monotonic stock increases and verifies that duplicate/bad inputs do not trigger the collaborator. Every published Python fence is executed in order by the existing repository test suite. External purchase delivery, transactional behavior and third-party service availability are explicitly outside this local model.

**Editorial content gate:** definitions, explicit input contract, mathematical invariant, complexity assumptions, counterexamples, separation of pure policy from external effects, readable naming, change-oriented reasoning, six independently solvable exercises and three primary technical references. All cross-language prerequisites and URLs are preserved.

**Still missing:** wider GoF pattern taxonomy, architectural foundations, network packet-level coverage, TLS/cryptography primitives, and systematic independent review of all chapters. Passing CI does not mean human peer review or demonstrate hiring readiness.

Sources: Google's public [code-review design/complexity criteria](https://google.github.io/eng-practices/review/reviewer/looking-for.html), Martin Fowler's [refactoring boundary](https://martinfowler.com/bliki/RefactoringBoundary.html) and the Python [dataclasses](https://docs.python.org/3/library/dataclasses.html) documentation.
