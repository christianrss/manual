# Editorial review checklist (Edition 2)

Use alongside AGENTS.md and EDITORIAL.md. This checklist is a human-review aid, not a completeness claim.

1. **Scope:** One clear question; no company names in vendor-neutral theory pages.
2. **Prerequisites:** Each symbol, concept and tool defined locally or linked to a published prerequisite.
3. **Derivation:** Reproduce the result from stated assumptions; explain invariants or correctness argument.
4. **Complexity:** Input variable, data-structure representation, cost model, worst/expected/amortized qualification.
5. **Failure model:** A counterexample and a clearly stated condition where the method is unsuitable.
6. **Executable proof:** Example and test with edge cases; translated implementations must work independently.
7. **Engineering reality:** Operational cost, error budget, capacity assumptions, monitoring or security where relevant.
8. **References:** Primary source titles, resolvable URLs, exact mapping of claims to citations; don't copy passages.
9. **EN/PT parity:** Same correctness guarantee, same source set, warnings and trade-offs; localized code still runs.
10. **Navigation and SEO:** Stable ID, canonical route, related published topics, descriptive title and alt text.
11. **Review status:** Keep outstanding gaps visible. Passing automated checks does not establish academic completeness.

Prioritize quality over volume. When necessary, split large technical domains into multiple articles rather than hide missing proofs behind a long overview.
