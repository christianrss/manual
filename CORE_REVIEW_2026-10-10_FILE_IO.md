# File descriptors and buffered I/O — focused review (2026-10-10)

Scope: one substantive bilingual OS chapter, ordered track integration, reciprocal links from processes/heap allocation and contextual link from PostgreSQL WAL, with independent finite-state tests. This is **not** an audit of all Linux filesystems.

**Descriptor contracts.** Single-process FD table, lowest available FD reuse, duplicate descriptors sharing a mutable open-description offset, independent opens sharing file bytes but not cursor, exact in-memory read/write/seek/close. Beyond-EOF writes insert dense zero bytes in the teaching bytearray; **empty** writes after seek do not extend the file. Invalid FD, count or payload raises with no mutation; descriptor flags, inode lifetime, rename/unlink, permissions, fork and concurrency are intentionally excluded. Source APIs: Linux `open(2)`, `dup(2)`, `write(2)`.

**Persistence contracts.** A second snapshot model separates visible bytes from the last acknowledged synced snapshot. `append` changes visibility; modeled `fsync` updates the stable snapshot; modeled `crash` discards post-sync changes. This is deliberately **not** a simulator of Linux page cache, writeback ordering, torn writes, filesystem journals, device honesty or real power failures. The chapter explicitly describes why syncing file content does not necessarily persist its directory entry and why user-space `fflush` differs from file durability. Sources: Linux `fsync(2)`, OSTEP filesystem chapters.

**Independent evidence.** `tests/test_file_descriptor_contracts.py` uses integer open-description IDs and immutable file byte strings, contrasting the published example's Python-object references and `bytearray`. It checks all `sum(10**k for k in range(5)) = 11,111` operation traces per language, exact returns/errors, file state, FD reuse, offsets and sharing identity; plus invalid inputs and seek-past-EOF edge cases. The crash oracle independently computes visible/synced byte prefixes over all `sum(4**k for k in range(7)) = 5,461` append/fsync/crash histories **per language**. All code fences run in both published translations under repository CI.

**Not established:** real POSIX conformance, partial I/O retries, file locking, system crash durability, directory rename persistence, atomic filesystem replacement, journaling, concurrent race freedom, hardware storage failure semantics, or academic peer review.
